# 人脸匹配与人物确认

## 视频抽帧与代表人脸修复（2026-11-13，待发布）

旧实现对 10 秒以内的视频只取开头一帧，其他视频每约 10 秒采样一次，且未比较人脸正侧角度或清晰度。现改为优先读取压缩视频的实际时长，每约 0.5 秒采样，长视频均匀采样最多 120 帧。抽帧长边限制为 1280，限制解码线程与超时；不读取冷归档原片。

每帧保留检测到的所有人脸。使用五点关键点的鼻眼位置与眼距估计正侧角度，并结合清晰度、原始脸部尺寸和检测置信度选择代表图；头部倾斜不会直接当作侧脸惩罚。相似度至少 0.65 的重复外观优先保留质量较好的图，同帧出现的人脸不能合并；只与最佳代表比较，避免沿相似脸逐步串成同一人。此分组不赋予人物身份，无法确定的外观仍分别保留，可能存在同一人的多张图。亲属相似脸、严重侧脸、遮挡及短于采样间隔的出镜仍需真实素材验证。

Web、iOS、Android 单份影像的人脸匹配新增「重新查找人脸」，调用原分析接口并提交可选的 `{"refresh": true}`。服务端保留既有 ID、已确认身份、忽略、撤回禁止自动匹配标记及自动关联证据，仅更新匹配到的未处理裁剪并补充遗漏结果；未再次检出的旧结果也保留，不需要先清空人工样本。未保存选择时禁用重查，失败保留页面结果。读取和普通分析继续复用缓存，不会自动重扫全库。响应新增可选 `refresh_supported`，新客户端连接旧服务端时隐藏重查入口。模型版本、特征格式、数据库和旧媒体协议不变。

验证使用独立本地 MySQL 8.4 测试库、合成短视频与公开 OpenCV 样例，不使用真实家庭影像推断准确率。公开样例组成的双脸视频能保留后段两张清晰代表图；低相似的模糊外观可能额外保留，未强行并入已确认身份。部署、已有视频重查和已安装旧版 App 与新后端的真机组合尚未执行。

## 管理员集中确认与家庭记忆采访

Web 管理员侧栏直接进入「人物与宠物确认」，或打开 `/yearly/face-review`（根路径部署为 `/face-review`）。页面集中展示待确认人脸、相似人物与已确认参考图；点击推荐只是选中，点击「确认人物」才保存。可逐项确认、改选或忽略，支持分页和查看已处理项。右侧直接显示来源影像与采访，不必逐张进入影像详情。

「分析下一批照片」每次最多处理 20 份已就绪的照片 / Live Photo，每组 5 份串行请求，可在组间停止；不会自动扫描全库或提取冷归档原片。视频仍可从影像详情按需分析。

「记忆采访」先展示待确认的人物问题（有候选时询问是否本人），也允许手动补充漏检人物和宠物。整张影像关联与逐脸身份分开保存，只有逐脸明确确认能成为人脸参考样本。采访使用已有画面描述、已确认人物和管理员回答，每次提出一个相关问题；回答后继续追问，推荐带有来源摘录的标签。无法在对应来源中逐字找到依据的标签不会展示，已有标签与纯人物姓名不重复推荐。

小记草稿直接采用本轮尚未保存的管理员回答，可编辑后保存；不把模型生成的画面故事写成家庭记忆。「保存标签与小记」合并勾选的标签并追加审核后的小记，保留已有内容。人物关联单独保存，采访生成或阅读不会修改影像标签、小记或人脸身份。

人脸匹配仍为本地推理；采访使用现有 OpenAI 配置、`gpt-4.1-mini` 和智能搜索共享的月预算，发送已有描述、人物名称、文字记录和回答，不重新上传照片。读取页面不调用 AI；开始采访或提交回答才调用。提问和建议保存到新增 `media_interview` 表，来源内容不变时再次准备复用缓存；人物或影像内容变化会提示更新。调用失败保留网页中尚未提交成功的输入。已生成的对话保存在服务端；尚未提交的输入仅在当前页面切换影像时保留。

## 单份影像入口

管理员在 Web 影像详情、iOS「影像操作 → 编辑影像」、Android「编辑影像」中展开「人脸匹配」，点击「查找这份影像中的人脸」。每张脸显示裁剪图；视频同时显示抽样时间。选择人物后点击「确认人物」，立即保存人脸身份并关联既有人物档案，无需再保存整份影像。其他编辑内容仍按原流程保存。

首次使用没有参考样本，需要管理员为每张脸选择人物。合照必须逐脸选择；上传时关联了某个人、人物头像或文件名，都不会被当作人脸身份训练依据。之后处理其他影像时，会推荐最多三个足够相似的人物，并显示已确认的参考脸，管理员可选择、改选、忽略或保持待确认。相似度是向量余弦值，不是识别正确率。

## 启用

这项能力独立于 OpenAI 搜索，本地 CPU 推理，不需要 OpenAI Key，也不会把人脸画面或向量发送给外部模型服务。模型下载仅发生在管理员显式运行安装命令时，应用启动和普通浏览不会自动联网下载。

```bash
# 在既有虚拟环境安装可选 CPU 依赖。
uv pip install --python .venv/bin/python -r backend/requirements-faces.txt
./scripts/manage.sh test migrate
./scripts/manage.sh test setup-face-models
```

在对应环境配置中设置并重启 API：

```dotenv
FACE_MATCHING_ENABLED=true
# 可选；默认项目 .local/face-models，容器需设置可持久保存的绝对路径。
# FACE_MODEL_DIRECTORY=/var/lib/yearly/face-models
# 可选；默认 0.45，仅用于候选推荐，不自动确认人物。
# FACE_MATCH_THRESHOLD=0.45
```

正式环境使用 `production` 替代 `test`，按现有升级流程先备份、迁移，再重启。默认关闭。未安装可选依赖或模型时，已有上传、浏览、搜索和手动人物关联继续正常工作。

视频分析可能超过普通元数据请求时长，客户端分析请求及 Nginx 人脸路由使用 180 秒等待时间；部署时同步更新根路径或子路径 Nginx 模板。普通接口的超时保持原值。

采用 OpenCV YuNet 2023mar（MIT）与 SFace 2021dec（Apache 2.0）。模型及许可证从 [OpenCV Zoo](https://github.com/opencv/opencv_zoo) 下载，模型文件通过固定 SHA-256 校验。实现参考 [OpenCV 官方检测与识别教程](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)。默认 0.45 是候选初始阈值，未用本家庭数据校准，不能据此声称实际准确率。

## 处理范围与存储

- 照片与 Live Photo 分析已生成的压缩静态预览，Live Photo 动态部分暂不分析。
- 视频只读取压缩视频，按实际时长每约 0.5 秒采样，均匀抽取最多 120 帧；无法探测时长时才回退到影像记录或 60 秒。时间戳为约数，短暂出镜可能遗漏。
- 影像尚未上传完成或预览未生成时，提示稍后重试，不读取或解冻冷归档原片。
- 每份影像按需分析，检测结果及「没有清晰人脸」都持久保存；再次打开或普通分析复用结果，点击「重新查找人脸」才补查。当前版本不后台扫描全库。
- 人脸特征、归一化位置、裁剪缩略图和确认人保存在新增的 `media_face_index`、`media_face` 表，模型版本与来源 SHA 分开记录。特征不写入旧媒体接口、审计内容或分享接口。
- 候选每次根据当前有效的已确认样本计算；纠错、忽略、删除来源影像后立即影响后续推荐，无需重建模型。来源影像在回收站时不参与匹配，恢复后重新参与。

## 纠正与清除

改选人物后再确认，会更新参考样本及本功能新增的人物关联，保留原有手动关联。选择「待确认」可撤销该脸的确认身份；「忽略这张脸」可排除路人或误检。

「清除本影像的人脸样本」删除本影像的检测、裁剪与参考样本，并移除本功能新增的人物关联。已有手动关联保留，可以重新分析。

数据库完整备份包含人脸样本。便携 JSON 清单维持原格式，不导出人脸特征和裁剪；恢复清单后人物关联仍保留，人脸参考库需要重新分析、确认。
