## 人物与宠物关联

档案支持所有人物与宠物，同一份影像或日记可以同时关联多位人物和宠物。下文的孩子关联规则也适用于其他人物与宠物；详见[人物与宠物](pets.md)。

## 数据流与完整性

浏览器选择原件 → 范围读取元数据 → 4 MiB 分块计算 SHA-256 和 CRC64/XZ → 用户确认 → API 创建逻辑媒体 / 多孩子关联 / 任务 → API 签名每份分片 → 浏览器 PUT 到 OSS → API 从 OSS 获取权威分片清单并完成合并 → HEAD 验证大小与 CRC64 → 全部逻辑资源完成才发布媒体。

原件使用 `originals/YYYY/MM/UUID.ext`，兼容预览使用 `previews/YYYY/MM/UUID.ext`，不使用用户路径，不重用对象 Key。合并请求附带 `x-oss-forbid-overwrite=true`。分片 ETag 只作为 OSS 完成分片的标识，不作为整个文件 MD5。浏览器先计算整文件 CRC64，服务端比较 OSS 整对象 `x-oss-hash-crc64ecma`。SHA-256 为浏览器计算值，记录于数据库及对象元数据。HEAD 的 SHA-256 元数据是上传时的声明，不能单独证明对象字节 SHA-256。CLI 完整备份会逐字节分块重算 SHA-256，作为独立审计。

上传 API 不接收二进制原件，不修改 EXIF 或原件字节。默认列表、头像和日记封面通过 OSS 图片处理加载最长边 480px、质量 70 的 WebP；详情加载最长边 1600px、质量 80 的 WebP，HEIC / HEIF 也由 OSS 转换。视频列表仅加载 OSS 截帧封面，完全不预加载视频原件。私有签名有效期 300 秒，前端在有效期内复用预览 URL。`/media/{mid}/files/{fid}/url` 默认 `purpose=preview`；只有显式 `purpose=original` 或 `download=true` 才返回原件。

视频由独立 `generate-previews` 工作进程生成 H.264 / AAC MP4，最长边不超过 1280px、短边不超过 720px，最高 30fps，CRF 28、码率上限 2.2 Mbps、faststart。HLG / PQ 输入通过 FFmpeg tone mapping 转为 SDR。按 SHA-256 去重，每个唯一视频只需读取一次原件，生成 `previews/video-v1/{sha256}.mp4`，完成后播放只读取该副本。工作进程下载到临时目录，检查大小和实际 SHA-256，再转码上传；结束清理临时文件。缓存状态保存在 MySQL `video_preview`，不计入原件清单和备份，丢失后可重新生成。MySQL 命名锁确保同一个库只有一个生成进程，异常退出的 processing 任务下次启动重试；failed 任务通过 `generate-previews --retry-failed` 重试。新增已完成上传和历史视频都由工作进程自动发现。

图片支持按钮、滚轮、双指缩放与放大后拖动。视频播放器提供进度、音量、倍速和全屏，点击播放才加载视频数据；Live Photo 默认使用照片和视频叠放预览，电脑悬停、手机长按或点击 LIVE 时播放，结束、松手或滑动取消后淡回静态照片。原文件按钮标注原件大小，HEIC 原件仅在用户主动查看时使用 heic-to 兼容解码。生产 CSP 保留 `worker-src 'self' blob:`。预览不支持的格式显示提示，绝不自动回退下载原件；原始视频编码是否可播放仍取决于浏览器，可下载原件在系统播放器打开。

OSS 图片处理与截帧可能有处理费用，生成视频预览也有首次读取流量、额外对象存储和 CPU 开销；节省的是后续重复浏览与播放的流量。生产建议把工作进程放在 OSS 同地域服务器，并按实际账单检查收益。

浏览器每份文件顺序分片上传，每片失败自动重试 3 次并重新签名。任务有效 7 天，签名有效 15 分钟，下载 URL 有效 5 分钟。重新打开页面后从“接着珍藏”选择原文件，SHA-256 和大小必须一致，恢复时读取 OSS 已上传分片并跳过它们。浏览器没有后台永久运行保证，大视频上传时应保持前台。多个 Live Photo 资源分别恢复，最后一份完成后媒体出现。

完整性错误返回 409，媒体不会发布。若已合并对象与声明不一致，保留记录供核查，重新创建上传任务。每日清理会中止过期分片，保留已完成对象以供恢复调查，不执行自动物理删除。

## Bucket 与 RAM

1. Bucket 访问权限为私有，关闭公共读写，开启阻止公共访问。
2. 开启版本控制。应用不授予删除权限，清理器只中止分片。版本控制与离线备份共同使用。
3. RAM 专用用户参考 `deploy/oss-ram-policy.json`，将 bucket 名替换为实际值，仅授予 originals / previews 前缀的 GetObject / PutObject / AbortMultipartUpload / ListParts。备份工具使用同范围权限即可。
4. `OSS_REGION` 必须是如 `cn-hangzhou` 的地域标识，endpoint 为 `https://oss-cn-hangzhou.aliyuncs.com`。使用官方 SDK AuthV4 签名，永久密钥从不下发浏览器。
5. 浏览器 CORS 参考 `deploy/oss-cors.xml`。AllowedOrigin 精确为家庭站点 origin，允许 PUT / GET / HEAD，允许签名与内容头，暴露 ETag 和 CRC64。开发时单独添加 `http://127.0.0.1:5173`，生产移除开发来源。
6. URL 签名由数据库中的文件 ID 推导 Key。接口没有任意对象 Key 签名能力，且上传授权仅任务创建人可以获取。

不要关闭 SDK 的 CRC 检查，不要授予 Bucket 公共访问来解决跨域问题。调试 CORS、签名时查看 OSS request-id，请勿把完整带签名 URL 粘贴到日志或公开问题单。

从本地环境发布到服务器后，必须在 Bucket CORS 中增加浏览器实际访问的 origin。修改应用的 `ALLOWED_ORIGIN` 或 Nginx CSP 不会同步修改 OSS；仅允许本地开发地址时，文件仍可入队、任务仍可创建，但直传会报“OSS 网络请求失败”。HTTP 和 HTTPS、不同端口分别属于不同 origin，不能互相替代。

可用下面的无文件写入预检核对实际站点；替换示例域名和地域。成功响应应允许请求中的 Origin、PUT 和 Content-Type；预检成功后，再从该站点使用合成文件验证真实上传及完整性。

```bash
curl -i -X OPTIONS 'https://your-private-bucket.oss-cn-hangzhou.aliyuncs.com/verification/cors-probe' \
  -H 'Origin: https://yearly.example.com' \
  -H 'Access-Control-Request-Method: PUT' \
  -H 'Access-Control-Request-Headers: content-type'
```

## 中国内地 Endpoint 与自定义域名

新开通的中国内地 OSS 账户可能受到默认公网域名访问、默认域名预览或流量接入限制。实际限制以当前账户控制台和 OSS 官方提示为准，不假设仅填 Bucket endpoint 就一定可用。

可行部署路径是准备已备案域名，例如 `media.example.com`，在 OSS 控制台完成域名绑定，按控制台要求配置 CNAME、HTTPS 证书，再设置 `OSS_CUSTOM_DOMAIN=https://media.example.com`。SDK 使用 `is_cname=True`，仍保留正确 `OSS_REGION` 进行 V4 签名。前端 CSP 和 CORS 同时匹配站点与 OSS 域名。该域名必须直接指向 OSS，避免将数 GB 媒体流量绕回应用 Nginx。

签名时使用的域名必须与实际上传请求域名完全一致，不要在生成 V4 URL 后自行替换 Host。HTTPS 页面不得使用 HTTP OSS endpoint。使用适用地域的 OSS 自定义域名路径，并按账户能力复核下载 / 预览响应，所有上传大小与校验不受格式预览能力影响。

## 照片解析

exifr 通过 Blob 的分段读取器读取 JPEG、PNG、WebP、HEIC/HEIF、TIFF/DNG 和部分 TIFF-based RAW 的 EXIF / XMP / IPTC。配置保留日期字符串，避免无时区 EXIF 被浏览器先转换到 UTC。读取到的 Make、Model、LensModel、Software、Orientation、ISO、曝光、光圈、焦距、闪光灯、白平衡和 GPS 等原样保存。常用时间、坐标、设备、尺寸独立存储。

格式容器、厂商 MakerNote 或浏览器导出方式均可能导致字段缺失，CR3 / 厂商 RAW 等不保证完整解析。可上传保存这些原件，未读字段保持未知。原始 JSON 是浏览器实际解析结果，并不等于文件所有字节所承载的每一种厂商标签。元数据每个逻辑媒体限制 1 MiB，超出需保留原件后使用离线工具检查。

GPS 纬经度从 EXIF 或 QuickTime ISO6709 获取，海拔从可用字段读取，GPS 时间、方向等保存在 raw JSON。无默认地理编码或第三方位置请求。手工地点和 GPS 修正仅更新数据库，raw JSON 继续保留原值。

## 视频解析与时间可信度

有界 ISO-BMFF walker 按 box 范围读取，跳过 mdat，最大深度 12、总 box 数 12,000、单叶最多 1 MiB、元数据总读取 8 MiB。不把数 GB 视频载入内存。支持常见 MOV / MP4 的 mvhd 时长、tkhd 尺寸与旋转、stsd 编码、hdlr 音轨、mdhd/stts 恒定帧率近似及 QuickTime keyed metadata 的日期、位置和标识。

VFR、特殊音视频 track、旧式 ©day / 厂商私有字段、超出读取预算或不常见封装可能无法完整解析，不能把所有提取值都当成权威。原始 numeric QuickTime creation seconds 保存在 raw JSON，因厂商 UTC / 本地写法差异，默认不据此强行生成当地时间。只有可解释的 CreationDate 字符串进入可靠日期候选。

时间优先级为用户修正、EXIF DateTimeOriginal、EXIF CreateDate / 可靠 QuickTime CreationDate、文件修改时间（低可信度）、未知。无时区字符串保留原当地日期，只有明确偏移时计算 UTC。文件修改时间展示的是设备当前时区解释的文件 mtime，仅作备用候选，不宣称是拍摄日期。

系统保存原始时间、原偏移、原时间来源和独立修正时间。修改修正时间不会覆盖原元数据。详情清空修正可恢复原值。需要将低可信度时间改为未知时，使用上传前时间确认的“拍摄时间未知”选项。

## Live Photo 与 iPhone 限制

可靠配对使用照片的 ContentIdentifier（包括 Apple MakerNote 的 `0x0011` 标识）与 MOV 的 `com.apple.quicktime.content.identifier`。系统不会仅根据同名文件自动配对。识别到照片配对标识但没有对应 MOV 时，上传队列显示「LIVE · 缺少动态文件」；此时继续上传只保存静态照片，不能恢复未收到的动态内容。若系统同时去掉了配对标识，网页无法判断它原来是否为实况照片。

没有标识时，在批量上传列表将静态 HEIC/JPEG 的“手动配对”指向对应 MOV，组合为一条逻辑 media，两个 media_file 分别保存，孩子关联只对逻辑媒体生效。用户可在上传前解除配对。详情页与分享页采用 [WebLivePhoto](https://github.com/link9596/WebLivePhoto) 的叠层交互，默认静音播放压缩 MP4（可点击声音按钮开启），两个原件各自提供下载入口；只有主动查看原文件才加载原始 MOV。

iPhone Safari 从照片图库选择的文件可能经过格式转换、编辑导出，也可能只提供静态资源。纯 Web 无法强制取得 PhotoKit 原始照片和所有 pairedVideo 资源。想保留原件，应在系统照片中导出“未修改的原片”到文件 App，并双文件导入。系统只保证所选字节无损上传，不根据扩展名宣称相机原件真实性。

Mac「照片」App 直接拖拽到浏览器通常只交付静态导出副本。保留实况需在「文件 → 导出 → 导出未修改的原片」导出，再将照片与配套 MOV 一起导入；以网页队列出现 LIVE 为配对成功依据。照片和视频分别解析 Apple MakerNote、QuickTime/ISO 两种 meta 容器的配对标识。

### iPhone 原生上传

已有 SwiftUI + WKWebView App 新增原生批量上传助手：顶部上传图标 → 系统相册多选 → 原始资源提取 → 检查双资源、拍摄信息及人物/宠物 → 确认上传。保留原有网页浏览和 Live Photo 播放方式，无需先导出到“文件”App。旧单张桥接仍兼容保留。

PhotoKit 读取 PHAsset 的未修改 `.photo` / `.video`，Live Photo 同组 `.photo + .pairedVideo`；只有完整尺寸编辑后资源可用时会明确提示，不混用不同版本。原始字节直接写入私有缓存，不转 HEIC/JPEG、不转码 MOV。使用可取消的 PHAssetResourceManager 字节流，以支持 iCloud 下载进度、取消和磁盘预算。

原生端按 4 MiB 流式计算 SHA-256 与 CRC64/XZ，上传按 API 任务实际返回的 `part_size`（当前代码默认 **16 MiB**，与上文历史 4 MiB 文案不同）。复用 `/uploads`、`/{id}`、`/{id}/sign`、`/{id}/complete` 及现有去重、关联和 HEAD 校验。一次创建 Live Photo 两份资源，全部完成才发布。原生请求可选携带 `Idempotency-Key`，服务端用原有元数据 JSON 保存回执，避免创建响应丢失后重复创建；无需数据库迁移。

任务和缓存跨启动保存；进入后台暂停，前台续传；强制结束后需继续任务，不承诺无限后台运行。缓存上限 8 GiB，预留 512 MiB。原生元数据中 PhotoKit 辅助日期/GPS 与原始嵌入值分开，不把导入时间当拍摄时间。详见[中文 iOS 开发、使用、免费安装与续签说明](../ios/README.md)，包含实际测试范围和未完成的真机验收项。免费 Personal Team 的签名需按 Apple 的 7 天有效期重新安装续签。

### 照片确认后仍停在系统相册

WebKit 已登记[多选照片准备期间没有反馈的问题](https://bugs.webkit.org/show_bug.cgi?id=325067)：原片下载、格式转换结束前，系统选择器可能一直保留在屏幕上，网页尚未收到文件。单选和更换浏览器也可能出现相同现象，不能仅凭界面判断是 iCloud 导致。网站不能在这一步获取下载进度或强制关闭系统相册。

上传页提供“相册卡住？直接粘贴照片”入口：在系统“照片”App 中选择照片 → 分享 → 拷贝照片，然后返回网页，在粘贴框内长按并选择粘贴。图片通过用户主动触发的 paste 事件进入原有队列，检查后再点击上传；不需要再次打开网页相册选择器，也不依赖要求 HTTPS 的程序化剪贴板读取接口。只接收图片文件，不插入剪贴板里的 HTML 或文字。

粘贴的是系统提供的副本，可能经过格式转换，或缺少拍摄日期与 Live Photo 动态部分。队列明确标记“粘贴副本”；有 EXIF 拍摄时间时沿用原时间，只有文件修改时间或没有时间时默认标记为“拍摄日期未知”，避免把复制时间当成拍摄时间。页面按收到的文件字节上传，不再压缩；需要相机原件时仍应使用文件导入。

批量导入可按 [Apple 的原片下载步骤](https://support.apple.com/en-us/111762)，在“照片”App 中选择文件 → 分享 → 导出未修改的原片，保存到“我的 iPhone”，待下载结束后再回网页点“从文件导入”，在系统菜单中选择文件 / 浏览。无需关闭 iCloud 或下载整个照片库。文件入口不限制媒体类型筛选，以便使用系统文件浏览器；实际支持格式仍由上传 API 校验。

网页收到文件后才显示读取数量和哈希进度；单个文件读取失败会列出文件名并继续处理其余文件。选择器未交付文件时只显示说明，不伪造 iCloud 下载进度。

## 重复导入与孩子关联

上传创建接口会以媒体类型、原件角色、SHA-256 和字节数匹配已完成且未回收的媒体。相同原件改名后再次上传仍复用原记录；Live Photo 同时比较静态与动态原件。命中后返回 `duplicate=true`、空任务列表和提示，前端显示“已存在”，不再上传 OSS、不改变原有归档日期和手工顺序，并将此次选择的孩子合并到已有孩子关联。已有原件的附带兼容预览不会重复保存，响应提示说明这一点。文件名相同但内容不同的文件正常保留，回收站记录不会自动恢复或占用新上传结果。

上传页首次使用且仅有一个孩子时默认选中该孩子；已有明确的“家庭时光”空选择会保留。选择孩子后立即应用到当前所选、尚未创建上传任务的文件，每行显示实际关联孩子。单个文件仍可在详情中修改关联。

## 追加时的日期确认

指定时间线日期追加文件时，开始上传前会比较所选、尚未创建任务的文件日期。优先使用用户修正的当地拍摄日期，其次使用解析出的拍摄 / 创建日期；仅有文件修改时间时明确标注待确认，明确标记未知的文件不参与比较。日期不同会弹窗按日期列出文件，可选择保留在追加日期、分配到各自对应日期，或取消检查；确认之前不创建上传任务。日期未知的仍保留在追加日期。此操作只设置 timeline_date，不修改原件或原始拍摄时间；每一天内仍按上传队列顺序整理。已创建任务的断点续传保持此前归档日期，重复导入保持已有记录位置。浏览器 File API 没有文件系统创建时间，不能把修改时间称作创建时间。


## 每日文件夹

文件夹属于一个确定的归档日期，支持单层分类、自定义名称，并与当天根目录的照片、视频自由混排。默认先显示文件夹，再显示当天未归入文件夹的影像；文件夹内的内容不会同时在当天根列表重复展示。年龄时间线和回收站仍以影像平铺展示。孩子筛选会查找文件夹中的关联影像；空文件夹为家庭共享。

影像只能批量移入同一天的文件夹。修改影像归档日期导致跨天时，自动移出原文件夹。文件夹内追加上传沿用日期核对提示：保留当天则进入文件夹，按文件日期移动则放到对应日期的根列表。重复文件复用已有影像和原位置，不因重复上传自动移动。

删除文件夹只移除分类，影像（含回收站内影像）移回当天根列表，原件不变。便携备份包含文件夹和成员归属，也兼容没有文件夹表的旧清单。


## 独立头像

孩子档案支持直接选择 JPG、PNG、WebP、HEIC / HEIF 图片（最大 20 MB），本地预览后随档案保存上传。浏览器按中心裁出正方形并压缩到不超过 512×512 的 JPEG，不携带原图 EXIF / GPS。独立头像仅保存压缩副本，原始家庭影像仍需从正常上传入口收藏。

头像沿用私有 OSS、分片完整性校验和短期签名读取，按 `purpose=avatar` 与普通影像隔离；不会出现在媒体列表、日历 / 年龄时间线或回忆数量中。头像对象保存在 `avatars/` 下，计入实际存储用量并包含在原有完整备份 / 恢复流程中。已有照片仍可直接设为头像。更换或清除只改变档案引用，不删除家庭原件。


## 拖动整理与恢复默认排序

日历时间线可直接拖动照片 / 视频调整同一天的顺序，拖到同日文件夹中间时显示移入提示，拖到卡片左右两侧插入排序；多选后拖动会移动所选的本日影像。拖动文件夹标题或右侧手柄可将文件夹放在照片、视频之间，文件夹内也可多选拖动排序，并拖到顶部区域移回当天时间线。跨日期拖放不执行移动，调整日期仍使用已有日期操作。

默认顺序使用有效拍摄当地时间（人工修正优先），从新到旧；时间相同时按记录 ID 倒序，未知拍摄时间排在当天末尾。普通上传不覆盖该顺序；手动调整过上传队列时才保存自定义顺序。日期栏“恢复默认排序”清除本日文件夹及全部活动影像（含文件夹内）的自定义顺序，文件夹恢复置前，影像按拍摄时间排列；文件夹内的同名操作只恢复该文件夹。恢复操作覆盖未加载或被筛选隐藏的内容，确认提示明确说明范围；不会改变文件夹归属、原始元数据及其他日期。

根目录混排由 `POST /api/timeline/reorder` 保存，以 kind 与 id 共同标识项目，服务端按当天完整列表计算顺序，保留筛选隐藏和未加载内容。影像和文件夹原有排序接口也使用同一根目录排序规则；文件夹内部仍独立排序。复用已有 sort_order 字段，无需额外数据库迁移。


## 实况预览交互与验收

实况预览由 `LivePhotoViewer.vue` 承载，参考 WebLivePhoto 的 MIT 实现，来源固定文件版本和许可证保存在 `frontend/THIRD_PARTY_NOTICES.md`。没有引入外部 CDN 脚本或 Apple LivePhotoKit。静态图与动态预览始终采用 contain 完整显示，收到 `playing` 事件后才淡出照片，结束或取消时恢复静态图；遵守减少动态效果设置。

打开详情仅获取图片及动态预览签名，视频使用 `preload=none`，悬停、长按或点击 LIVE 后才下载。手机按下同步调用静音 play 进行预热，180ms 后显示动态画面；10px 以上移动、第二根手指、取消、松手、离开窗口或页面隐藏均停止。LIVE 按钮支持点击和键盘操作，可播放完整一遍。静态照片页签保留缩放及原始 HEIC 查看，实况页签可主动查看动态原件。全屏按钮支持 iPhone WebView 内的整屏预览，Escape 先退出全屏。

预览未生成时保留照片，每 15 秒重查状态；播放失败或缓冲超过 20 秒显示重试，重试绕过签名缓存重新授权。绝不自动回退原始 MOV。关闭预览会释放视频和定时器。分享页仍只调用原有分享授权接口，过期后清空播放器。

自动测试使用 Mock 和合成图片/视频，覆盖静态图保留、长按预热、取消后的延迟播放事件、待生成状态、签名刷新、播放拒绝、清理和全屏返回。iPhone 低电量模式、真实网络中断与 HEVC 原件兼容性仍需真机验收。存储原件、配对信息、上传与数据库协议均不变。
