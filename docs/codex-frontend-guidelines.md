# Codex 前端开发规范

适用范围：前端页面、组件、样式及交互开发。遵循当前任务和目标项目的既有约定；按实际功能采用适用条款。

## 1. 开发前先理解项目

- 阅读目标目录的 `AGENTS.md`、相关页面、公共组件、设计变量与验证命令。
- 优先复用现有技术栈、组件库、图标、表单、请求和状态管理机制。
- 明确用户任务、主要动作与数据来源，再确定页面结构。
- 保留无关改动。需要重构或引入依赖时，先判断是否属于当前任务。

## 2. 视觉层次清楚，装饰克制

- 优先用底色、间距和排版组织内容，避免层层套卡片、重复描边、粗重阴影与无意义渐变。
- 保留输入框、键盘焦点、选中项、错误与拖放目标所需的操作边界。
- 主色用于主要动作和选中状态；成功、警告、错误保持稳定语义，不能只靠颜色传达状态。
- 每个操作区突出一个主要动作；危险操作与普通操作明确区分。
- 复用语义化设计变量，统一圆角、间距和图标笔画；不新增同义变量或使用未定义变量。
- 嵌套圆角与间距协调；连续曲率仅按需要增强，并验证浏览器兼容与普通圆角回退。

## 3. 排版可读，布局稳定

- 遵循项目字号体系；未建立体系时，正文和表单可从 14–16px、辅助信息从 12–13px 起步，按实际阅读环境校准。
- 暗色模式分别检查底色、对比度与字重，不机械反色，也不统一把正文改成细体。
- 普通文本以至少 4.5:1、大号文本以至少 3:1 的对比度作为验收目标。
- 动态数字使用 `font-variant-numeric: tabular-nums`，预留合理宽度，避免计数变化推动周围控件。
- 网格随容器调整列数；图片、骨架与实际内容比例协调，减少加载时布局跳动。
- 长标题、文件名和翻译允许合理换行或省略；文件名截断保留扩展名，并提供读全路径。
- 列表优先呈现浏览与决策必需的信息，详细元数据按需展开。

## 4. 中文输入与表单正确

- 中文输入法选字期间，Enter 只完成组词，不触发搜索、保存、发送或换页；使用现有组件机制处理 composition 状态。
- 单行、多行输入和提交快捷键各自明确；不能为了支持 Enter 提交破坏正常换行。
- 字段错误就地说明原因和修正方法，修正后更新状态；不能只用短暂 Toast 承载错误。
- 保存中防止重复提交；失败保留用户输入，并提供明确的继续操作路径。
- 外部数据在入口完成必要校验，内部依赖清楚的数据契约，避免逐层重复判断。

## 5. 阅读位置由用户掌控

- 用户正在翻阅历史内容时，新消息、新上传或后台刷新不得强制拉走页面。
- 自动跟随仅在用户处于最新内容附近、且任务需要时启用；离开后停止，提供“跳至最新”等明确入口。
- 关闭预览、展开分组和返回列表时，保持合理的阅读锚点。
- 切换筛选条件或日期范围需要重置结果时，清楚显示新范围。
- 折叠后保留数量和异常提示，不把需要处理的问题一起隐藏。

## 6. 动效与进度服务真实操作

- 拖拽、缩放和进度条拖动即时跟手；状态切换采用短过渡；轻量确认可按需要提供小幅按压反馈。
- 只过渡实际需要变化的属性，避免 `transition: all`、大幅悬停位移和持续装饰动画。
- 已知尺寸先占位，内容加载后自然出现；仅在真实流式场景使用流式文字效果。
- 明确区分加载、空、失败与完成；百分比和成功状态来自真实数据。
- 无法测量进度时显示阶段或不定进度，不伪造精确百分比，不刻意增加等待。
- 支持 `prefers-reduced-motion`，关闭非必要动画后功能仍完整可用。

## 7. 按任务选择组件

- 补充解释用 Tooltip，并提供键盘与触屏读取路径；必要信息直接展示。
- 简短结果用 Toast；有真实撤销能力时可使用带撤销入口的 Snackbar。
- 持续问题用行内提示或页面 Alert；小型必要决策用 Modal 或就地确认。
- 需要对照列表编辑时用侧边抽屉或适合手机的 Bottom Sheet；长内容、多步骤任务优先独立页面。
- 命令集合用 Dropdown 或 Action Sheet；字段取值用 Select、Radio 等，二元即时设置可使用 Switch。
- 少量选项优先便于直接比较；较多候选按需要增加搜索；不能把示例中的选项数量当作固定门槛。
- 媒体查看使用适合的预览组件；新手引导可跳过或关闭，不为落实规范增加产品没有的功能。

## 8. 浮层和操作可预测

- 按钮使用“删除文件”“继续编辑”等具体动作，不只写“是 / 否”。
- 普通可恢复操作不叠加多层确认；危险操作保留明确的取消路径。
- 有未保存改动时避免误触遮罩丢失内容；只读浮层应容易退出。
- 使用现有组件的焦点管理；模态浮层约束焦点范围，关闭后回到合理触发位置。
- 不把禁用 Esc 设为所有对话框的默认行为；关闭、取消和提交的含义清楚区分。
- 批量操作明确数量、目标及作用范围；“全选”说明是当前页、已加载项还是全部筛选结果。

## 9. 筛选和日期范围明确

- 高频筛选外露，低频条件收纳；查询较慢或需组合条件时，集中应用筛选。
- 已选条件始终可查看和清空；合并全选标签不得改变筛选语义。
- 日期快捷项显示实际起止日期，日期边界、包含关系和时区与服务端一致。
- 日期控件支持适合跨度的年月定位或直接输入；不可用日期说明原因。
- 图表、明细和导出联动时保持条件一致，展示当前筛选范围。

## 10. 手机、键盘与国际化可用

- 按移动端任务重新组织布局，不把桌面多栏界面等比缩小；不擅自删减业务功能。
- 图标视觉尺寸与点击热区分开设计，常用触控操作以约 44 × 44 CSS px 作为起点；热区不重叠、不抢滚动。
- 核心操作不依赖 hover、精细拖拽或设备震动；图标按钮有可访问名称，键盘焦点可见。
- 手机面板适配内容、软键盘和可用空间，不机械套用固定高度比例。
- 按钮和操作栏适应翻译长度，字符不被固定行高裁切；使用加长文案检查布局。
- 需要 RTL 时，逐项核对文字、图标和媒体控件方向，不机械镜像所有内容。

## 11. 拖拽、分屏与通知按需实现

- 拖拽通过插入线或目标高亮说明落点，区分排序和移入容器；提供适合键盘与触屏的替代入口。
- 操作失败如实反馈，不靠动画制造成功假象；手动排序不被后台刷新悄悄覆盖。
- 已有可调整分屏时，提供取消拖动、恢复默认比例和恢复折叠面板的路径，保护两侧内容最小宽度。
- 分屏折叠按内容与任务决定，不机械套用“拖过 80%”等示例阈值。
- 待处理事项可用数量，新内容可用圆点；处理后消除，营销和装饰不滥用提醒徽标。
- 数字徽标增长时锚点稳定；使用 `99+` 等简写时，详情仍可查看真实数量。

## 12. 控制实现复杂度

- 先完成当前任务的最小完整实现，不为单次使用提前抽象 helper、组件或通用框架。
- 没有必要不增加依赖、`try/catch`、确认弹窗和重复校验。
- 几乎不会发生的边界或并发问题，说明概率和影响并获得用户确认后再增加处理，不以“理论上更稳”膨胀代码。
- 不因视觉改动顺带改变数据、权限或存储语义；隐藏按钮不能代替服务端权限校验。

## 13. 交付前必须验证

- [ ] 打开真实页面，验证本次改动涉及的主要任务路径。
- [ ] 检查适用的浅色、暗色、中文、英文、长文案和大数据量状态。
- [ ] 检查常用桌面宽度、390px 和 320px 窄屏；无意外溢出、遮挡和操作冲突。
- [ ] 检查输入法选字、键盘、触屏、滚动锚点与减少动画偏好。
- [ ] 检查加载、空、失败、完成，以及保存失败后的输入保留。
- [ ] 运行项目要求的类型检查、构建和与行为变化相关的测试；纯样式不写复刻实现的测试。
- [ ] 保存适用的页面截图；截图使用虚拟数据，不暴露账户、凭据或私人内容。
- [ ] 说明改动、验证结果及未覆盖项；区分本地检查、提交、部署和线上验证。

完成标准：相关任务在真实页面中可用。代码生成、截图美观和构建通过都不能单独证明完成。

## 附录：仅用于当前家庭影像项目

以下内容不作为其他项目的默认要求：

- 列表读取缩略图，详情读取压缩预览；用户主动选择“查看原文件”后才读取原件，预览失败不自动回退原件。
- 时间线按日期组织，支持月份折叠、排序和日期定位；手机单日超过 8 项时按既有约定折叠。
- 卡片优先展示影像，只在存在自定义标题时显示标题；批量上传优先公共属性批量设置。
- 人物和宠物可共同关联同一文件，筛选不重复展示，原件只保留一份；成长视角按档案开关呈现。
- 分享内容日期范围与有效期分开设置，有效期遵循现有 1 小时至 7 天的约定。
- 分享访问范围、排除项、有效期与资源权限由服务端核验，前端保持清楚的只读阅读体验。
