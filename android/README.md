# Yearly Android 原生客户端

使用 Kotlin、Jetpack Compose、Material 3 和 Media3，复用现有家庭影像 API。最低 Android 8.0（API 26），当前编译与目标 SDK 为 34。包名为 `family.yearly.app`。

## 功能

- **登录与会话**。配置完整家庭站点路径、图片验证码、账号登录、安全会话恢复、退出、切换站点及修改密码。会话使用 Android Keystore 的 AES-GCM 密钥加密保存，账号密码不持久保存。
- **时间线**。左侧常驻可拖动日期轴，按真实日历跨度定位并跟随阅读位置。按归档日期或上传时间浏览，支持升降序、关键词、人物／宠物、上传人、媒体类型、日期范围、全部展开／收起、月份折叠、单日超过八项折叠、游标分页。支持最多 200 项多选整理、分享与用所选影像写日记。
- **媒体查看**。图片左右切换、双指缩放及双击缩放，原生视频播放、动态照片预览与重播，信息、拍摄元数据、归属和修改日志。
- **整理与编辑**。影像标题、批次、备注、标签、归档日期、拍摄时间及偏移、未知时间、地点／坐标、分享开关、人物关联，批量添加／移除／替换人物、修改批次与归档日期、文件夹移动和排序。
- **日记与文件夹**。日记创建、阅读、编辑、关联影像、封面、分享开关与回收站。文件夹创建、改名、解散、分享开关、排序、内容分页与移出影像。
- **原片上传**。系统相册多选、文件导入、流式 SHA-256 与 OSS CRC64/XZ、原始拍摄元数据、批次确认、人物关联记忆、重复提醒、持久任务、暂停／继续／取消、断点续传及完成后查看影像。服务端确认完整性后才显示完成。
- **家人与账户**。孩子、家人、宠物档案、头像、出生时间、成长年龄和里程碑，账户创建、用户名／密码／角色／启停管理，归属权限与分页修改日志。
- **分享与恢复**。日期范围或所选影像分享、1 小时至 7 天有效期、复制链接、系统分享、同范围新建、撤销及访问计数。回收站恢复影像与日记，归档原件解冻、校验后导出文件及保存相册。
- **外观与缓存**。跟随系统、浅色、深色。列表缓存按完整站点路径与账号隔离，有效期五分钟，缓存空结果，写操作失效。签名资源地址即时读取，缩略图与预览独立缓存。

## 动态照片与原件

文件导入可按元数据中的相同 Content Identifier 配对照片与 MOV。标准 XMP Motion Photo 可从原始图片尾部提取独立 MP4，图片原件保持原字节。播放复用服务端生成的兼容动态预览。

不同手机厂商的私有动态照片封装需要对应样本验收，目前未覆盖所有厂商格式。系统／云端媒体提供者可能限制原件或位置元数据访问，应用请求原始媒体格式并保留实际返回字节，读取不到的拍摄日期显示未知。

导入优先读取 EXIF 拍摄／数字化时间和视频创建时间，保留原件中的时区偏移；兼容 Android 视频常见的紧凑日期格式，并优先保留 iPhone MOV 中的本地创建时间。没有原件拍摄日期时，依次使用提供者的相册日期、EXIF 文件修改日期、源文件修改日期和加入相册日期作为归档依据，确认页标明实际来源。手动指定的批次归档日期优先。相册与文件日期保存在辅助元数据中，不冒充原件拍摄时间，也不使用本机导入缓存的日期。Android 文件选择器未必提供真正的文件创建时间；所有日期都不可读时保持未知，可手动归档。

原件日期在导入时读取，不再为旧版本队列重新解析日期。确认或已开始的任务保留其原有上传字段，以保持重试请求一致。

1.0.3 将日期轴两端改为“年份 + 月日”两行完整日期，避免同月内的起止日期显示为相同年月。刻度范围跟随当前筛选、归档／上传日期模式与升降序。

Android 10 及以上可将校验后的原件写入系统相册。Apple Live Photo 的静态图与 MOV 分别写入相册，Android 相册如何展示由相册应用决定。Android 8／9 使用系统文件夹导出。配对资源保存期间失败会清理本次创建的文件。

上传缓存保存在应用的 `noBackupFilesDir`，上限 8 GiB，并预留 512 MiB 可用空间。应用进入后台会暂停任务，返回后可手动继续。重启恢复任务时核对服务器已有分片。清除应用数据或卸载会删除未完成的本机原件缓存。

## 构建

需要 JDK 17、Android SDK 34、Build Tools 34.0.0。首次构建需联网下载 Gradle 与依赖。可用 Android Studio 打开本目录，或从仓库根目录执行。

```bash
# 本地测试、Lint 与 Debug APK
./scripts/android.sh verify

# 个人安装用签名 Release APK
./scripts/android.sh release

# 安装到 adb 已授权设备
YEARLY_ANDROID_DEVICE='adb devices 显示的设备编号' ./scripts/android.sh install
```

Release APK 位于 `.local/android/Yearly-android.apk`。脚本首次运行会在 `.local/android/` 创建个人签名密钥及 `signing.properties`，权限限制为当前用户可读写。后续构建复用同一密钥以支持覆盖安装。请备份该目录下的签名文件，避免遗失升级身份。

Debug APK 可通过 `./scripts/android.sh debug` 复制到 `.local/android/Yearly-debug.apk`。Debug 与 Release 签名不同，使用同一包名，实际使用请选择稳定的 Release 签名。

普通安装请输入证书有效的 HTTPS 家庭站点，例如 `https://example.com/yearly/`。Debug 构建额外允许模拟器回环地址 `10.0.2.2` 和本机回环地址进行虚拟接口验收。Release 使用 HTTPS。

服务器应部署当前仓库版本，并完成账户审计、分享访问、预览归档相关迁移 `0013`～`0015`。客户端直接使用当前上传协议及幂等键，不再探测旧服务器能力。权限、分享范围、原件可用状态与上传完整性最终由服务端核验。

## 验证

```bash
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleRelease

# 协议测试：先构建，再明确指定测试模拟器
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb -s emulator-5580 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5580 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5580 shell am instrument -w family.yearly.app.test/androidx.test.runner.AndroidJUnitRunner
```

本次 8 项单元测试验证 OSS 校验向量、分块流式校验、站点地址策略、动态照片原字节提取、任务状态恢复、日历日期刻度、上传日期的本地时区，以及导入日期格式、偏移和归档来源优先级。Android 14 模拟器的 4 项仪器测试覆盖实际 JPEG EXIF、MP4／MOV 创建日期、扩展名为空的缓存原件、日期读取前后字节不变、MediaStore 与文件提供者的时间单位和缺失列，以及独立 TLS MockWebServer 上的安全会话、缓存命中／空结果／写后失效、原生上传创建、归档日期请求、旧待上传任务日期重读、手动日期优先、跳过已有分片、任务重启续传、来源校验及对象存储凭据隔离。对象存储模拟服务拒绝签名中不存在的 Content-Type，确保分片 PUT 与后端签名一致。测试使用独立配置与缓存，不改应用的站点、登录状态和上传记录。

界面验收使用虚拟档案、抽象测试图片和合成视频，检查四个主页面、浅色／深色、320dp 窄屏、筛选、图片翻页、视频与动态预览、影像编辑保存、指定影像分享、文件选择与原片准备。截图保存在仓库忽略的 `.local/android/`。签名 Release 包已安装到 Android 13 手机并验证冷启动；修正分片签名请求头后，真实站点的一条约 2.7 MB 视频任务已从失败恢复为完成。真实站点的其余功能、云端相册、大批量真机上传及各厂商动态照片尚未全部验收。

1.0.2 已覆盖安装到同一 Android 13 手机；用户重新选择两份真实文件后，在确认页分别核对到 EXIF 拍摄时间与相册日期归档提示，保留在确认页供用户继续。日期相关模拟器验收还检查了系统文件选择器导入照片、视频与只有源文件修改日期的图片，以及旧队列未知日期的显示；测试样本未上传至真实站点。

1.0.3 已通过 8 项单元测试、无错误 Lint 和 Debug／签名 Release 构建，并覆盖安装到 Android 13 手机。日期轴使用同月虚拟样本检查 320dp 浅色、390dp 深色、完整起止日期与拖动定位；真机也核对了同月上传日期的两端日期，之后恢复为归档日期模式。
